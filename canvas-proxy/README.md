# @basketikun/canvas-proxy

Infinite Canvas 的本地转发代理。浏览器直连第三方 AI 接口时经常被 CORS 拦截，启动它之后，网页会把请求先发到本机，再由本机转发到目标地址。

代理只做转发：不改写请求体，不校验 API Key，不落盘任何日志。

## 使用

```bash
npx @basketikun/canvas-proxy@latest
```

默认监听 `http://127.0.0.1:23210`。把这个地址填进 Infinite Canvas 的「配置 → 本地代理」，并打开开关即可。

带上 `@latest` 是因为 npx 会缓存已下载的版本，不加就可能一直运行旧版本。

可选参数：

```bash
npx @basketikun/canvas-proxy@latest --port 23210 --host 127.0.0.1
```

也支持 `PORT` / `HOST` 环境变量。

### 允许的来源

代理默认只接受画布页面的来源，其他网页即使能连上也会拿到 403（浏览器侧表现为跨域失败）。默认白名单：

```
http://localhost:5173  http://127.0.0.1:5173
http://localhost:3000  http://127.0.0.1:3000
```

如果你从别的地址打开画布（例如用 Docker 镜像起的 `http://localhost:8088`，或 DSH 桌面端插件的地址），需要把自己的来源加进去。`--allow-origin` 可重复：

```bash
npx @basketikun/canvas-proxy@latest --allow-origin http://localhost:8088
```

也可以用 `CANVAS_PROXY_ALLOW_ORIGINS` 环境变量，多个来源用英文逗号分隔。

启动时会打印实际生效的来源列表。不确定自己页面的来源时，打开「配置 → 本地代理」，界面上给出的启动命令已经带上了当前页面的来源。

被 `file://` 打开的页面带的是 `Origin: null`，默认同样被拒绝；确认自己需要时才加 `--allow-null-origin`。

## 转发规则

把完整目标地址接在代理地址后面：

```
http://127.0.0.1:23210/https://api.openai.com/v1/models
        └─── 代理地址 ──┘└──────── 目标地址 ────────┘
```

请求方法、请求头（除 `host` 等逐跳头外）、请求体原样转发，另外带上 `origin` 与 `x-canvas-proxy: 1`；响应状态码、响应头和响应体原样返回，并补上该来源对应的 CORS 头。SSE 流式响应按块透传，不做缓冲。

请求体上限 32MB，超过返回 413；上游返回 3xx 时不跟随跳转，直接把状态码和 `location` 交给调用方，避免重定向绕开目标地址校验。上游 120 秒内没有返回响应头会主动断开，避免请求一直挂着；已经开始的响应体流式转发不受这个时限影响。

访问根路径 `/` 会返回代理版本信息，可用于连通性检测，不会记入转发日志。

## 转发日志

每转发一条请求就在终端打印一行，包含时间、方法、完整目标地址、上游状态码和耗时：

```
4:05:42 PM GET https://api.openai.com/v1/models -> 200 0.9s
4:05:43 PM POST https://api.openai.com/v1/images/generations -> 200 26.4s
4:05:45 PM GET https://api.example.com/v1/models -> failed (fetch failed) 1.6s
```

日志在收到上游响应头时打印，所以流式请求会立刻出现一行，而不是等整段响应结束。日志只输出到终端，不落盘，也不包含请求头和请求体，因此不会泄露 API Key。

## 安全提示

代理默认只监听 `127.0.0.1`，仅本机可访问。`--host` 填非回环地址时必须再加 `--allow-public`，否则直接拒绝启动——那等于把代理开放给同网络或公网上的任何设备。API Key 依然由浏览器持有并随请求转发，代理本身不存储。

请求体上限 32MB（与 canvas-agent 的 30MB 对齐），超出返回 413 而不是继续读进内存。

代理会拒绝转发到云厂商元数据端点（`169.254.169.254`、`metadata.google.internal`、`100.100.100.200` 等）以及链路本地、CGNAT、`0.0.0.0`、广播地址，避免被用来读取实例凭证。局域网和本机地址仍然放行，因为代理本机生图/推理服务是它的用途之一。域名会先解析再判断，用自己的域名指向元数据地址也会被拒绝；剩下的缺口是解析与连接之间的时间差（DNS rebinding），要完全堵住需要在连接层再校验一次，对本工具的定位不成比例。

来源白名单同样只是降低风险：它挡住的是"任意网页都能把本机代理当内网转发器"这类用法，不会限制本机上的脚本或命令行工具。
